# OctoAcme Project Management Docs

This folder contains OctoAcme's project management guidance, from validating an initiative through delivery, release, and continuous improvement. The documents are intended to provide a shared, practical reference for project teams and new teammates.

## Project management process at a glance

OctoAcme uses a customer-first, iterative project lifecycle. **Initiation** clarifies the problem, desired outcomes and success measures, stakeholders, risks, resources, and whether the work should proceed. **Planning** turns approved work into an actionable backlog by defining scope, acceptance criteria, estimates, the Definition of Done, dependencies, risks, milestones, and a release plan.

During **execution**, teams coordinate through standups and regular delivery and stakeholder updates, track work on a project board, and deliver small, reviewed pull requests. Developers and QA build quality in through tests, CI checks, security scanning, and manual validation where needed; PMs track progress, risks, and blockers and escalate issues through the agreed paths. For **release**, the team confirms acceptance criteria and checks have passed, prepares release notes, smoke tests, and rollback or mitigation plans, deploys, verifies, and communicates the outcome. After sprints, releases, milestones, or incidents, the team holds a retrospective and tracks a small set of improvement actions with owners and success criteria.
